# Application assembly

## Claim

A selected configuration loads, resolves its declared dependencies, and assembles the expected application or agent graph. Distinct profiles or programmatic builders may expose different capabilities and should be verified separately.

## Entry and proof

- Use the repository's public builder or runner. Controlled model and service adapters can establish construction, routing, and state behavior without claiming external availability.
- When the claim includes real dependency initialization, use the production-facing initialization path with those dependencies available.
- Inspect the resolved tool set, routes, state updates, and failure behavior against the relevant design contract.

Give the generated skill the target repository's exact commands and configuration paths. A successful build alone does not establish a live model response, stored artifact exchange, or remote tool call.
